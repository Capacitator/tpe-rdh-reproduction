# Supplemental NIST test of actual block-r1 outputs

The original campaign tested full HMAC-SHA256 digests for block-r1. This separate addendum tests the two-bit `r1` values actually consumed by the cipher, using a predeclared non-overlapping key pool and the same NIST parameters. It preserves all earlier streams and reports.

1. Read [`docs/AUDIT.md`](docs/AUDIT.md) for the input-selection rationale.
2. Generate 100 distinct 1,000,000-bit streams and run official NIST STS 2.1.2:
   `python3 experiments/run_r1_output_protocol.py --sts-dir /path/to/sts-2.1.2`
3. Verify stream/report hashes and generate the complete per-test summary:
   `python3 experiments/summarize_results.py`
4. Run unit tests:
   `python3 -m pytest tests -q`
5. Recreate the updated old-format Word report as a new file:
   `python3 experiments/make_final_report.py`
   It appends the actual-r1 NIST results to the corrected report and refuses to overwrite an existing report.

All first-level p-values, second-level uniformity results, pass/fail/N/A counts, official raw reports and hashes are written under `output/`. No code or parameter is changed to target p-values; this experiment only corrects the tested data to include the actual derived block-r1 values in addition to the full PRF digest outputs.

The 100 MB ASCII input is a deterministic expansion of the 100 binary streams. It is regenerated by the protocol script and is included in the full downloadable artifact bundle; it is excluded from the Git commit to avoid storing a redundant large text file.
